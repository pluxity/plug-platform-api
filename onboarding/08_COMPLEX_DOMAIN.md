# 8단계: 복합 도메인 및 트랜잭션 (Complex Domain)

이 단계에서는 단순한 CRUD를 넘어, 여러 엔티티가 얽혀 있는 복잡한 도메인을 다루고 트랜잭션의 범위를 관리하는 방법을 학습합니다.

## 목표
- `Station`, `Line`, `StationLine`의 N:M 관계 이해.
- `@Transactional`의 범위와 전파(Propagation) 이해.
- 복잡한 생성/수정 로직(`Facade` 패턴 또는 서비스 오케스트레이션) 분석.

## 도메인 분석
`core` 모듈의 `StationService.kt`와 관련 엔티티들을 분석하세요.

**핵심 포인트**:
1.  **관계 매핑**: `Station`과 `Line`은 직접 연결되지 않고 `StationLine`이라는 연결 엔티티를 통해 매핑됩니다. 이 구조의 장점을 고민해보세요.
2.  **트랜잭션 관리**: `StationService.save` 메소드는 `Facility`, `Floor`, `StationLine`, `StationCode` 등 여러 테이블에 데이터를 씁니다. 중간에 에러가 발생하면 모든 데이터가 롤백되어야 합니다.
3.  **상속 구조**: `Station`은 `Facility`를 상속받습니다. JPA에서 상속 관계가 어떻게 테이블로 매핑(`JOINED`, `SINGLE_TABLE` 등)되어 있는지 확인하세요.

## 실습 과제

### 과제 1: 지하철 노선 관리 기능 구현
1.  **브랜치 생성**: `onboarding/step-8-complex` 브랜치를 생성하세요.
2.  **기능 구현**:
    - `Line` 엔티티(호선 정보)를 생성, 수정하는 기능을 구현하세요.
    - `Station`에 `Line`을 추가하거나 제거하는 API를 구현하세요 (`POST /stations/{id}/lines`).
    - **제약 조건**: 이미 연결된 노선을 다시 추가하려고 하면 예외를 발생시키세요.

### 과제 2: 환승역 조회 쿼리 작성
두 개 이상의 노선(`Line`)이 지나가는 `Station`(환승역)을 조회하는 기능을 구현하세요.
- JPA Method Query 또는 JPQL/QueryDSL을 사용하여 구현해보세요.
- 결과에는 역 이름과 지나가는 노선들의 이름이 포함되어야 합니다.

### [필수 과제: QueryLog 확인]
`application.yml`에서 SQL 로그를 켜고, 과제 2번(환승역 조회) API를 호출했을 때 쿼리가 몇 번 나가는지 카운트하세요.
- 쿼리가 너무 많이 나간다면(N+1 문제), `Join Fetch` 등을 사용하여 튜닝하고 결과를 비교하세요.
